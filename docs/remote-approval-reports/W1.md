## Contract decisions

| Question and section | Choice implemented |
| --- | --- |
| How to use W0 below kv-core without a cycle (§13.1, Appendix F)? | Implement and re-export the existing kv_ipc::remote traits; kv-core already adapts these. SoftwareFileKey accepts a caller factory. The compatibility harness supplies a newtype around W0 SoftwareDeviceKey. No duplicate provider/probe trait is defined. |
| How to persist remote metadata before kv-vault provides an API (§3.2)? | Providers return opaque metadata; reopen APIs explicitly require authenticated metadata. TPM/SE blobs, PCP names and DPAPI protected blobs must be AEAD authenticated by the owning helper/vault adapter. W1 does not substitute an unauthenticated long-lived metadata file. |
| Which TPM object template permits both operations (§3.1)? | A distinct ecc256:null child with SHA-256 name algorithm, fixedTPM/fixedParent, sensitiveDataOrigin, userWithAuth, sign, decrypt and noDA; neither restricted nor a fixed ECDSA/ECDH scheme. Accept exactly attributes 0x60472 when reopening, including rejecting additional attributes. A storage primary reloads the child. Linux approval keys remain V2; this provider implements DK. |
| What is the common ECDH representation (§3.1, A.1)? | Return only the left-padded 32-byte big-endian P-256 x coordinate. Parse TPM2B_ECC_POINT strictly, extract SE raw shared bytes, reverse CNG RAW_SECRET. W0 performs the RFC 9180 HKDF/AEAD. |
| What signature bytes are passed to W0 (§3.1)? | ES256 is 64-byte P1363 r||s. TPM plain DER is converted strictly. Native SE/CNG raw signatures are passed through. Hello is exactly 256-byte RS256 and receives the original message, without an extra prehash or the vault challenge. |
| How to select software (§3.1)? | Only explicit SoftwareFileKey/DpapiDeviceKey constructors. Hardware failure returns an error. Unix storage requires a private current-owner directory, create-new 0600 file, exact 32-byte scalar, and no symlink following. Factory rejection is bounded. |
| How to constrain opaque Windows key handles (§3.2, A.7)? | PCP and Hello names must match keyvalet.remote.<role>.<32 hexadecimal digits>. Persist and pin the role and public key through authenticated metadata; reject other namespaces and roles before opening a handle. This internal name format is a W1 decision. |
| How to use one PCP key for both operations (§3.1)? | Request an ECDH P-256 machine key with signing and agreement usages, then self-test ES256 and raw ECDH before accepting creation. Unsupported dual use/raw export is an error and the new key is deleted. This choice is still awaiting real Windows measurement. |
| What does Quick presence mean (§3.1; general architecture §8.1.1)? | Report unlocked for hardware Quick keys as required by the device-key contract. PCP supplies no user-presence gate: the authenticated owner-session UI/helper policy must enforce the click. No TPM/PCP hardware-presence claim is added. |
| How to carry large envelope signing input (§5, Appendix C)? | An internal device_key request uses input_len followed by exactly that many bytes, capped at 128 KiB; replies are u32 big-endian result length + result + metadata JSON, capped at 8192 bytes. Before binary input, the same authenticated connection must answer operation=capabilities with ok=true/device_key_protocol=1. Legacy agents receive no binary bytes. The capability and operation share one timeout. Agent protocol 1 remains unchanged; document this extension in Appendix C. |
| What counts as an available presence signal (§6.10.1)? | All nine W0 raw fields across the five signal groups must be known. Any missing value is Away; an active remote session can provide a known awake virtual display. Native failures remain unknown. Raw values and platform extras remain local. |
| What are debounce startup/since/clock semantics (§6.10.1, A.6)? | Start Away; require a continuous five-second candidate; a flap cancels it. since is the candidate's first observation time. Backward wall-clock movement resets to Away. Tests cover all six directed state transitions, 119/120-second idle boundary, flaps and clock regression. |
| How to initialize macOS lock/screensaver signals (§6.10.1)? | Combine dictionary values with observed distributed notifications, conservatively preferring a true locked/saver signal. Missing dictionary fields and absent notification history remain unknown. Mac V1 follows the owner's console and reports remote_session_active=false. This startup behavior needs the usability follow-up below. |
| How exact is Linux input idle (§6.10.1)? | logind exposes idle hints rather than exact last-input age. With known hints/timestamp, non-idle maps to 0 and idle maps to hint age + the default 120-second boundary. Missing/invalid hints remain unknown. Preserve IdleHint/IdleSinceHint in raw extras. Exact configurable thresholds require a compositor/X11 source. |
| How to determine polkit registration (§6.10.1)? | Accept registration evidence from the session agent through an injected callback; observing a process is insufficient evidence. An absent callback result is Away. The agent owner must supply and revoke this evidence. |
| How often to report (§6.10.1, §16, A.6, Appendix C)? | Send debounced coarse state changes immediately and refresh unchanged hints every 60 seconds. A failed helper acknowledgment does not advance the sent cache. Reconnect invalidates it. This interprets the ambiguous 60-second wording as refresh cadence; delaying lock updates for a minute would conflict with the five-second transition requirement. |

## Review fixes

| Finding | Resolution and regression coverage |
| --- | --- |
| Hello metadata accepted overly broad key names. | Use the shared exact role namespace and 32-digit handle check. Tests reject substituted roles, prefixes, suffix lengths and nonhex characters, and exercise Windows metadata validation on macOS. |
| A restrictive process umask could create a software key with permissions narrower than the required exact 0600 and then make reopen fail. | Set 0600 explicitly on the new file before writing. Permission, create-new, symlink, writer/sync failure and cleanup tests use temporary owned files. |
| The Linux output reader could wait after the direct child exited if another process kept stdout open, escaping the intended deadline. | Drain stdout nonblockingly and require both successful exit and EOF within one deadline. Tests include inherited pipes, silent children, output limits, interrupted/would-block reads, read errors and wait errors. |
| DRM status existence checks could turn an I/O error into a skipped connector. | Use try_exists and preserve unknown/Away on errors. Missing power, disconnected/off displays, invalid status and a symlink loop are covered. |
| TPM public metadata allowed additional object attributes. | Validate the exact object created by W1 and reject added/restricted flags, invalid schemes/curve/policy, truncation and trailing bytes. Keep decoded public/private blobs as validated fields, with the private blob zeroized, instead of decoding immutable metadata again for every operation. |
| Native bridges and Windows snapshot interpretation had too little nonhardware test coverage. | Inject the actual macOS ABI function table and SE C ABI; test CF ownership/type checks, bounds, status failures and pinned metadata. Extract Windows snapshot interpretation so console/RDP/lock/display/input failures run on macOS CI. Native Windows adapters remain unmeasured. |

The review did not change the hardware fallback policy. All provider errors remain static and omit key material. Tests exercise actual production functions with injected inputs; no coverage exclusion attributes or hardcoded success results were added.

## macOS spike: measured

Machine: this repository's Apple Silicon Mac, macOS 26.5.1 (25F80), arm64; Apple Swift 6.2.3, macOS SDK 26.2. No installed KeyValet binary or daemon was used.

Run from the repository root in an unlocked owner GUI session:

```sh
xcrun swiftc rust/crates/kv-touchid/tests/spikes/hpke.swift -o rust/target-w1/hpke-spike
rust/target-w1/hpke-spike
```

Observed output and exit status 0:

```text
hpke_recipient=pass
raw_ecdh=pass length=32
same_key_es256=pass signature_length=64
```

Conclusion: on this machine, CryptoKit HPKE.Recipient accepts SecureEnclave.P256.KeyAgreement.PrivateKey for P-256/HKDF-SHA256/AES-128-GCM base-mode decrypt. The same SE object's encrypted representation can be reopened for ES256 signing, and raw SE ECDH matches a software peer. Production uses the W0 ECDH seam and common Rust HPKE implementation; its SE interoperability test also passed ES256 verification, raw shared-point comparison and HPKE open for DK and Quick, including an 80 KiB signing message. This is not a measurement on macOS 14 or under a locked screen.

Suggested §3.1 update: record the measured OS/SDK and the three successful results, replace the unmeasured-SE statement, and retain minimum-OS/ACL hardware scenarios as outstanding verification.

## Open questions

- Windows PCP dual-use ECDH/ES256, PCP peer-key import and RAW_SECRET support are unmeasured. A failed self-test keeps hardware unavailable and requires an architectural decision, rather than an automatic downgrade.
- AEAD metadata persistence and live authenticated agent reporting need the owning helper/vault/UI integration. W1 exposes the code seams and tests, and has not edited those unowned paths.
- Initial macOS lock/screensaver values were absent on this machine; presence remains Away until a reliable value or notification history exists. A reliable initial-state source needs measurement before broad rollout.
- Linux logind hints cannot provide exact last-input duration for arbitrary thresholds; compositor/X11 integration and polkit registration evidence remain required for desktops where these signals are unavailable.
- The dependency-free Linux busctl backend bounds each query to three seconds. Measure end-to-end polling latency under an unavailable/slow bus; batching or an asynchronous cached source may be needed to meet the real five-second transition target in that condition.
- Strong SE prompts, locked-screen ACL behavior, minimum macOS version, real Linux hardware/GUI transitions and Windows hardware/session behavior still need the listed manual runs. Windows scheduling follows the user's deferred-testing instruction.
