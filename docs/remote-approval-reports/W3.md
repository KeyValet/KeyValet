## Implemented behavior and trust boundary

The single binary loads a bounded, strict TOML configuration, checks that a public identity key
is available through helper IPC, fetches a 32-byte challenge, asks the helper to sign its raw
bytes, verifies with the relay, and opens a `kv-relay-v1` WebSocket. HTTPS/WSS use rustls; numeric
loopback HTTP/WS support local instances and CI. Redirects, credentials in URLs, query/fragment
configuration, private-key fields and transport path overrides are rejected. Session tokens
remain in memory. Error messages contain local categories, HTTP status or IO error kind.

Production code neither holds a private key nor signs, verifies, seals or opens an envelope. Raw
JSON preserves envelope whitespace and future fields. Only routing/framing fields are inspected.
Incoming envelopes, including malformed/future/expired shapes, reach the helper unchanged before
any relay ack. The helper's literal `ack: true` alone permits `POST /v1/messages/ack`; false,
helper errors, timeout, EOF and missing transport IDs do not authorize it. W2's unsigned
`pair_accept`/`approval_cancel` metadata hints are ignored without disconnecting or changing helper
state. Unknown controls and invalid/binary frames reconnect.

The WS pump is independent of helper delivery and HTTP sending. Application heartbeat and status
use 30-second periods. Missing pong, a closed socket or a full bounded inbound channel reconnects.
Sessions renew before expiry, with arithmetic and timer bounds for extreme peer timestamps.
Helper polling continues during relay authentication/network failure and commits outbound
ciphertext before attempting transmission. On each connection, waiting approvals are fetched and
helper-authorized acks complete before the FIFO sender becomes ready. Approval request/escalation
fanout uses `/v1/approvals`; decisions use `/reply`, cancellations use `/cancel`, and other
envelopes use `/v1/messages`. A whole FIFO prefix remains until the relay returns its exact
accepted count or explicit unary `ok: true` and the helper durably records its accepted receipt.
Only then is the local prefix removed. Unsolicited WS acks cannot remove disk entries. Poll replies
are acknowledged only after ciphertext commit; exact repeated ciphertext is deduplicated. Before
sending, the helper may retire an expired, already accepted or obsolete continuous prefix.
Incoming relay acks name both ID and type so request/escalate/cancel sharing an ID remain separate.

The exclusive spool uses ordered sequence filenames and arrays of ciphertext envelopes. Unix
directories/files are 0700/0600 with owner validation, `O_NOFOLLOW` and a process lock. Appends
and partial completions sync the file, atomically rename it and sync the directory on Unix.
Startup recovers complete temporary appends, replays the committed prefix after an interrupted
rewrite, and fails closed while preserving corrupt entries. IO runs on blocking workers so it
does not block heartbeat. Reconnect is 1, 2, 4, 8, 16, 32, 60 seconds, with server `Retry-After`
cooldown taking precedence. 4xx/partial acceptance never silently discards an envelope.

## Platform layout and W9 service integration

| Platform | Account and IPC | Configuration | Ciphertext queue |
| --- | --- | --- | --- |
| Linux | `keyvalet-relay`; `/var/run/keyvalet/relay.sock` | `/etc/keyvalet/relay-client.toml` | `/var/lib/keyvalet-relay/queue` |
| macOS | Per-user `dev.keyvalet.relay`; existing helper socket with relay selection | `~/Library/Application Support/KeyValet/relay-client.toml` | Sibling `relay-queue` directory |
| Windows | `NT SERVICE\KeyValetRelay`; `\\.\pipe\keyvalet-relay` | `C:\ProgramData\KeyValet\relay-client.toml` | `C:\ProgramData\KeyValet\Relay\queue` |

All fixed endpoints, labels, binary paths and service identities use shared `kv-platform::paths`
constants. Linux uses `/run/keyvalet/relay.sock`; `/var/run` is its runtime alias.
The client checks its service UID and the helper's `SO_PEERCRED` UID. macOS derives the actual
account home through the account database, checks the helper's root UID and audit-token signature,
and requires the installed helper binary path. It has no sudo fallback. Windows uses the existing
trusted pipe connector's service/publisher verification. The helper now hosts the dedicated relay
pipe with service SID/path/publisher enforcement. W9 must provision the account/SID before
restarting the helper and starting the relay service.

W9 should consume these [templates and integration instructions](../../rust/crates/kv-relay-client/service/README.md):

- [systemd unit](../../rust/crates/kv-relay-client/service/keyvalet-relay.service): create the
  non-login user/group, provision a read-only root-owned config, and expose only the dedicated
  helper socket. The unit uses `ProtectSystem=strict`, `PrivateTmp`, `NoNewPrivileges`,
  `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, empty capability sets and a private state
  directory. Reserve `keyvalet-relay.service` for the client; W2's server unit uses
  `keyvalet-relay-server.service`.
- [LaunchAgent plist](../../rust/crates/kv-relay-client/service/dev.keyvalet.relay.plist): install
  and bootstrap in the owner's domain with `KeepAlive`. Sign the binary with team `PWCRJPY7YC`,
  hardened runtime and identifier `dev.keyvalet.relay-client`. Enable it only after the signed
  daemon/agent relay subprotocol is available. `AGENT_REQUIREMENT` identifies `kv-touchid` and
  cannot authenticate this binary.
- [Windows provisioning template](../../rust/crates/kv-relay-client/service/windows-service.ps1):
  elevated `service install` registers an automatic SCM service under its virtual account,
  depends on `KeyValetHelper`, enables the service SID and configures recovery. Provision queue
  ACLs and config read access before starting. Helper pipe DACLs must admit the relay service SID
  and SYSTEM with peer verification. `service uninstall` stops/deletes registration and keeps
  configuration and queued ciphertext. Neither command was executed in this workflow.

## Review and corrections

The review covered trust enforcement, opaque forwarding, helper-owned ack, HTTP acceptance,
queue crash/recovery behavior, task cancellation, platform branches and service templates.

| Finding | Correction and regression evidence |
| --- | --- |
| Extreme session expiry could overflow subtraction or Tokio's timer | Saturating subtraction and bounded renewal timer; both `i64::MIN` and `i64::MAX` tested |
| Empty/mismatched sender groups could index an absent reply or confirm the wrong prefix | Reject before network access; malformed grouping tests preserve queue entries |
| WS handshake protocol failures were classified as network failures; a later protocol check was unreachable | Preserve HTTP cooldown and classify protocol errors; rely on tungstenite's required-protocol validation; missing protocol and 429 tested |
| W2 metadata hints could cause reconnect loops before signed traffic was handled | Ignore the two unsigned hint types; control-frame test proves normal envelope forwarding and intact outbound ciphertext afterward |
| A stale metadata size check did not bound a file changed before its read | Bound the bytes actually read; oversized and corrupt committed files remain intact |
| Integration tests could stop after relay DB acceptance but before durable local completion | Wait explicitly for committed dequeue; real W2 integration and outage tests check both delivery and an empty spool |
| Fake waiting responses converted opaque `RawValue` through `Value`, creating a WS/waiting race in exact-byte assertions | Serialize the raw envelope collection directly so both delivery paths preserve the same bytes |
| Workspace feature unification enables both rustls providers, making the default WSS builder ambiguous | Install an explicit ring process default while preserving an existing provider; a real TLS ClientHello regression fails closed as a network error when its loopback peer disconnects |

Native adapters were separated from command/configuration, protocol and FIFO logic so their real
system checks cannot leak into fake CI runners. No test reads an installed KeyValet template,
trust-checks an installed binary, contacts the installed daemon or requires root/sudo/GUI/hardware.

## Shared contracts and production prerequisites

The following original change requests are closed by the user-authorized W1–W5 joint acceptance:

| Original request | Final contract |
| --- | --- |
| Shared relay platform constants | `kv-platform::paths` defines each platform's relay endpoint, binary, service identity, config and queue; macOS has a separate relay code requirement |
| Public identity query | Shared `remote.relay.identity`, schema/allowlist and helper handler return public JWK plus bound device/account IDs |
| Authenticated relay IPC bridge | macOS audit-token relay selection, Linux service UID/socket and Windows service SID/pipe/publisher checks are connected |
| Durable helper outbox receipts and retirement | `remote.relay.outbound.ack`: ciphertext-bound SQLite receipts for `spooled`, `accepted`, `inspect`; client removes only accepted or helper-retired prefixes |
| Idempotent relay submissions | Identical full envelopes succeed without resetting ack or redelivery; altered ciphertext conflicts; split approval fan-out is supported |
| Signed cancellation and metadata controls | Client forwards the signed cancel envelope; relay routes it to original recipients even after resolution/expiry; unsigned controls remain advisory |
| Terminal invalid-envelope ack | Helper durably audits permanent rejection before ack; transient processing/provider/audit errors remain unacked |

The joint review also fixes per-type inbound ack races, presence fan-out, timeout auditing,
MCP result notices, the protected Windows worker's actual agent PID binding, the Windows Stop
pipe adapter and workspace-unified WSS provider selection. See
[the acceptance report](W1-W5-integration.md) for changed files and real-module regression evidence.

The shared untagged `remote::Response` cannot preserve nested `RawValue` through serde's buffered
enum decoding. W3 keeps its raw-compatible ok/result/error wrapper; this does not weaken helper
ack semantics or require the shared response to hold keys or interpret ciphertext.

Production bootstrap still needs vault AEAD-authenticated identity/device metadata, a real
DeviceMirror and a real credential policy/RequestRunner adapter before installing RemoteHelper.
Missing bootstrap remains `remote_unavailable`; no software identity is generated as a fallback.
W9 must consume the service templates and provision native identities/ACLs before service startup.

## Platform verification gaps

- Linux GNU production/test targets now type-check with the existing Zig cross compiler and
  isolated W3 caches; the client binary also cross-links. Actual service UID/socket trust checks and systemd execution still need a
  native Linux runner; cross compilation is not native service acceptance.
- Windows GNU production/test targets type-check and the client binary cross-links; these do not establish SCM install/uninstall,
  virtual-account behavior, pipe SID/Authenticode enforcement or NTFS power-loss durability.
  The spool uses write-through files and `sync_all`; std does not provide directory fsync on
  Windows. Validate these on native Windows before service rollout.
- macOS build/tests do not establish the new signed LaunchAgent/root-helper bridge's actual
  audit-token acceptance. No signing, service installation, sudo or hardware operation ran.
- Tests use loopback HTTP/WS and exercise WSS TLS construction with a rejecting loopback peer.
  Hosted HTTPS/WSS certificate, proxy and deployment runtime behavior still needs W9 smoke testing;
  the production client retains normal certificate verification.

Production rollout remains dependent on authenticated vault/provider bootstrap, the real policy
execution adapter and native deployment acceptance. The shared transport contracts above are closed.
