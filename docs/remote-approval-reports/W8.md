## Rust 核心与边界

- DK、AK_q、AK_s 通过 `DeviceKeyProvider` 的原生回调使用。手机初始化拒绝相同的三把公钥；原生回调的 ES256 签名在 Rust 中再按对应公钥校验。原生运行时没有软件私钥回退。
- 注册、DK 挑战认证、扫码 URI 校验、双设备 SAS 确认、W0 HPKE 封解、外层身份签名、收件设备/账户/发送者/过期时间绑定全部在 Rust。最新要求改为先完成 Google／Apple 登录和设备注册，再扫码配对；早期匿名入口已从 App 移除。W2 配对迁移后清除旧 session 并重新认证。
- `ApprovalView` 覆盖 §6.3 的设备、OS/保护级别、agent、cwd/user/pid、凭证引用/名称/类型、proxy-only、操作/方法/host/path/query key/body 大小、agent 自述目的、tier/min-level、合并数、到期、提供的 scope、时钟偏差和升级状态。Dart 无 digest、nonce、信封或签名接口。
- Decision 从已验证的待批记录构造，重用其 digest/nonce/到期和提供的 scope。T2、admin/unlock、standing 均使用 AK_s；原生后台只允许 AK_q 的 `per_use`。密钥操作失败不消费待批记录、不入待发队列。生物识别期间状态改变会在提交事务时再次核对。
- 设置页签发有限期/standing 的 credential、device、global Grant，以及锁定、模式、QueryGrants、revoke-all 等 Directive。T2 无人值守须准确输入执行端标签，默认 7 天；永久授予另有二次确认。当前短期设置票按 W0 验证器使用 Strong，产品 Quick 差异见变更请求。
- SQLite 使用 WAL、FULL、busy timeout、进程内 mutex 和跨进程文件锁。业务记录采用 DK ECDH 派生的 AES-GCM 存储键加密，AAD 绑定 bucket/id；数据库与 WAL 不存审批明文。bucket/id/到期/顺序是明文索引元数据。iOS 使用 App Group，Android 使用应用私有目录；拒绝软链接目录/数据库/锁，目录 0700、文件 0600。活动仅保留最新 200 条，持久状态和队列不会因查询上限被截断。
- 发件箱先落库、后发 relay；接受响应确认后才删除，过期对象不重发。认证和发件发送分别串行化，避免单次挑战冲突和并发发送打乱 FIFO。429/5xx、断网和进程重启保留待发密文。
- 前台 WS 使用 `kv-relay-v1`，30 秒心跳、65 秒失联检测、1–60 秒退避；连接后拉 waiting，再处理队列。暂停/恢复会取消旧任务并重新建立连接。原生后台直接运行 Rust，WS 有限时拉取；收到信封先提交本地事务，再 ack。后台 ack 失败仍返回已验证通知计划，后续重复信封重试 ack。
- silent 不响；经验证的 `approval_escalate` 更新同一 approval_id；「我不在电脑前」可使待批直接显示横幅。通知偏好控制横幅，静默记录继续保留。关闭/取消审批的状态持久化，重启或断网恢复时仍可移除旧通知。只把可信且未过期的缓存计划交给原生层；不信任推送里的 level、正文或 mode。
- W4 QueryGrants 的完整 Grant + `budget_left.calls_left` 解析为白名单视图，未知余额显示未知。设备页进入时依次查询 status、grants 和 audit；QueryAudit 最多 200 条，仅取事件代码、时间与结果，不传任何其他审计字段到 Dart。设备页最近 10 条合并执行端摘要，本机活动页仍只列本机签发。在线提示与设备状态分开，120 秒过期；成功撤销后同步剔除报告缓存中的 Grant。
- 诊断只有 schema、连接状态、计数与 away 标志，不包含设备标识、标签、凭证、目的、键、信封或 token。

## 原生薄层与双绑定

`flutter_rust_bridge` 固定 2.11.1，配置 `mobile/flutter_rust_bridge.yaml`，命令 `mobile/scripts/codegen.sh`；提交 Rust `frb_generated.rs` 与 Dart `lib/src/rust/`。代码生成使用 W8 产物目录内的隔离 manifest 和源文件软链接，普通检查/构建使用主工作区与共享 lockfile。

NSE 和 Android 后台走手写 C JSON ABI，头文件由 `mobile/scripts/generate-c-header.py` 同时生成到 NSE、iOS plugin、Android JNI。两套绑定复用 `view.rs` 的公开类型；C ABI 的 JSON 由这些类型序列化，原生消费后不传到 Dart 解析。

| 接口 | 用途与约束 |
| --- | --- |
| `kv_mobile_open(config, callback)` | 原生 worker 初始化目录/平台/设备标签/硬件种类，建立 Rust runtime；回调须具有进程生命周期 |
| `KvKeyCallback(slot, operation, input, output)` | slot 0/1/2 = DK/AK_q/AK_s；operation 0/1/2 = 65 字节 SEC1 公钥 / 64 字节 ES256 签名 / 32 字节 ECDH；ECDH 仅 DK |
| `kv_mobile_call` | `snapshot`、`sync`、`diagnostics`、`push_token`、`quick_decision`；没有任意签名、指定密钥或 Strong 命令 |
| `kv_mobile_free` | 单次释放 Rust 返回的 JSON 字符串 |
| Flutter Rust API | snapshot、前台生命周期、begin/confirm pair、decide、issue_grant、directive、preferences、diagnostics、账户登录生命周期；只有视图与意图，产品地址固定且无修改 API |
| Flutter platform channel | initialize、一次性通知 approval_id、pushToken；没有私钥/签名或布尔生物识别 API |
| iOS `KvNativePlugin.attest` | 原生 App Attest 的 challenge-hash 适配器；relay 验证契约待补，因此尚未接入注册 |
| Android `Integrity.attest` | 原生 Play Integrity 的 cloud-project/nonce 适配器；relay 验证契约待补 |

iOS 三把键均使用 Secure Enclave P256；DK 的设备绑定 opaque representation 存在 App Group，保护为 AfterFirstUnlockThisDeviceOnly，创建带跨进程锁。AK_q 为 WhenUnlockedThisDeviceOnly；AK_s 含 `.privateKeyUsage + .biometryCurrentSet`，签名直接使用 Secure Enclave + LAContext。批准键 opaque representation 留在主 App keychain；NSE 只读批准公钥缓存。DK 同一 opaque representation 的签名/ECDH 双用途仍需真机确认。

Android 三把键使用 AndroidKeyStore，优先 StrongBox，支持时回退 TEE，并检查实际 KeyInfo 的硬件安全级别。AK_q 要求设备已解锁；AK_s 要求每次 `AUTH_BIOMETRIC_STRONG`、生物识别变更失效，签名经 `BiometricPrompt.authenticate(CryptoObject(Signature))`。跳过提示后调用真实 `Signature.sign()` 应由 Keystore 拒绝；不是根据 Flutter 或 `local_auth` 的布尔结果放行。JNI 反射入口包含 release keep rules。

iOS `KeyValetNSE` 是独立 target，不启动 Flutter。默认正文为本地化的安全提示，`.passive`；解密验证后按 Rust 计划填摘要、threadIdentifier、类别、`.timeSensitive` 或 `.passive`。Quick 的 `UNNotificationAction` 带 `.authenticationRequired`，主 App 原生后台用 AK_q 签；Strong 打开 App。Android FirebaseMessagingService 直接走 JNI/Rust，静默和高优先级渠道更新同一 tag；Quick 使用需要解锁的前台服务，Strong 进入 App。

## kv-push 与接入

服务默认监听 `127.0.0.1:9608`，`POST /v1/push` 需 `Authorization: Bearer <KV_PUSH_RELAY_BEARER>`。请求限制 8 KiB，拒绝未知字段；只接受 provider token、approval_id、delivery.mode，不能接收信封或审批正文。

```json
{
  "device_push_token": { "platform": "apns", "token": "REPLACE_WITH_DEVICE_TOKEN" },
  "approval_id": "01ARZ3NDEKTSV4RRFFQ69G5FAV",
  "delivery": { "mode": "silent" }
}
```

APNs 使用 ES256 provider JWT、`mutable-content:1`、120 秒 TTL、approval_id collapse-id；默认 interruption-level 为 passive 且无声音，只有 NSE 的已验证计划可提升横幅。FCM 使用服务账户 RS256 OAuth、有限大小响应与 token 缓存，发送 high-priority data message，TTL 120 秒、collapse_key 同 approval_id；没有 FCM notification block。Provider 返回 429 映射为 429，其余故障为 502，不回传 provider 正文。生产端点固定为 APNs/Google 官方地址，测试可在私有字段注入本地服务。

所需外部配置：`KV_PUSH_RELAY_BEARER`（32–256 字符）、`KV_APNS_KEY_FILE`、`KV_APNS_TEAM`、`KV_APNS_KEY_ID`、`KV_APNS_TOPIC`、可选 `KV_APNS_SANDBOX=1`；或 `KV_FCM_SERVICE_ACCOUNT_FILE`，可选 `KV_PUSH_PORT`。这些键仅为推送服务凭据，不是设备审批私钥，文件不入库。

W2 尚未将消息发送接到 kv-push，也没有推送 token 更新接口；注册时可以提交 token，刷新时目前仅更新手机本地加密元数据。不能据此声称真实后台推送已接通。

## 共享契约变更请求与未决项

1. **W0 / kv-core 的 mobile feature**：桌面 `kv-core` 无条件依赖平台执行 runner，iOS 编译遇到缺少平台函数。现于 W8 mobile cfg 下用 `#[path]` 编译 W0 **未改动**的 `remote` 模块，复用原类型/HPKE/验签实现；没有复制一套协议。请求提供正式 remote-only feature 或提取库，解除源文件路径耦合。共享 lockfile 的 W8 依赖边已由共享工作区提供，W8 不改共享 manifest/lock。
2. **W0 / 产品短期设置 Grant**：当前 `verify_grant` 对 origin=settings 全部要求 Strong，J-R3b 的 1 小时设置票期望 Quick。手机按现有验证器使用 Strong；请求一起明确可 Quick 的边界，修改共享验证器/向量后再接入。
3. **W2 push 接入**：定义注册 push_token 为 `{platform, token}`、增加经过设备认证的 token 轮换/删除 API、将 approval_request/escalate 的路由元数据送 `/v1/push`，并处理 provider 429/5xx/无效 token。推送服务本身不能读审批信封。未接钩子时可用前台 WS，不能完成后台推送验收。
4. **W2 attestation 契约**：补 App Attest/Play Integrity 的一次性 challenge、回执字段、验证、重放策略和自建 relay 的显式关闭配置。当前只有原生适配器，不声称已验证 attestation。
5. **W2 配对完成状态**：本次使用现有 `PairCompleteResponse.extra.account_id` 处理匿名账户合并；手机只在本机 SAS Strong 确认和 finish 成功后存 peer。请求一个可查询两边 finish 状态的公开响应，避免 UI 仅靠用户确认执行端已核对。
6. **key_kind 与硬件恢复**：明确 Android `tee`/`strongbox` 的规范枚举和展示；生物识别登记变更/密钥失效后的设备重新配对、键轮换与旧设备吊销契约尚待补。当前失败即拒绝签名，不自动删除身份或降级软件键。
7. **W4 状态回执**：已按实际 `QueryGrants` 全 Grant + `budget_left.calls_left`、QueryAudit entries、DirectiveResult 白名单接通软件侧；真实 helper 应用票据、远端审计与设备状态联动尚需在设备环境联调。Grant 余额未得到执行端回执前保持未知。
8. **真实环境验收材料**：开发者账户可用权限、两个匹配的 App Group profiles、APNs p8/key-id/topic、FCM 项目与外部 `google-services.json`/服务账户、Play Integrity cloud project、Android 发布 keystore、用于完整交互式审批验收的已登记 Strong 生物识别真机。需以可被系统正常验证的发布/测试分发完成安装；不通过关闭系统验证补成“通过”。
9. **平台限制**：iOS arm64 设备/Apple Silicon Simulator，Android arm64/API 31+；Intel iOS Simulator、Android x86/旧 API、iOS 真机 DK 双用途、系统锁屏 Quick、真实 T2 交互式生物识别、推送声音/升级表现、NSE 与主 App 真实并发、TestFlight/Play 分发未验证。没有把这些缺口纳入软件测试通过数。

### 复核后修正的边界

1. 登录成功不能代替生物识别。Quick/Strong、Grant、Directive 继续使用原来三把硬件键与范围校验；未登录时在 Rust 中拒绝私有快照、配对、收件解密、通知计划与签发操作。
2. 用户由 provider + subject 标识，不按 email 合并。设备 DK 签名绑定 ID token 的 SHA-256、单次 attempt 和 state。Apple 另检查 nonce；Google 7.2.0 SDK 没有 nonce 参数，因此使用 DK proof 绑定一次性登录。Google azp 允许已登记的 Web/iOS/Android presenter。
3. 用户 token 仅保存在硬件派生的加密 SQLite；relay 存 token hash 与已验证的 provider/subject/email/name 元数据，审批仍为密文。API、诊断、日志和原生 account_status 不返回 token。
4. 退出先清理本地会话，再尝试远端撤销。迟到的 provider/restore/finish 响应不能重新登录；旧 restore/认证的拒绝响应仅清理原会话，不能误删新会话或新登录 attempt；已签发但本地取消的会话会尝试立即撤销。服务器拒绝 WS 会话时不能回退到离线通知缓存。
5. 每台手机仅保持一个活跃用户会话；重新登录失效旧用户/设备会话。会话过期、退出或设备吊销后 HTTP/WS 拒绝旧 Device token。
6. 扫码本身不占有执行端账户。只有双方 SAS 确认事务完成才设置 owner；pending 状态重新登录也不能提前占有。另一个已验证用户无法加入被占有的账户。
7. 新登录注册路径已补推送 token 上传，避免 registered=true 跳过原匿名注册后失去推送。APNs/FCM token 按设备/OS 校验，并在未登录/离线时保留到后续同步。
8. 旧配对测试把 exp=now()+601 当成超限，真实秒边界曾造成偶发 200。新增仅 harness 可用的固定时钟，使这个边界与限流测试稳定；真实 30 秒升级和 100 秒心跳测试仍使用真实传输时间。

### 外部配置与变更请求

- 配置 Google Web/iOS/Android client ID、同项目 consent/test users、正确包名与证书 SHA-1；配置 Apple App ID/Services ID、固定域名和 callback。不能复用 Simvito 的应用身份。
- W9/部署：部署已验收的 kv-server，给服务注入上述公开 OAuth 环境变量。现有 deploy/relay/keyvalet-relay.service 未声明 EnvironmentFile，建议由部署工作流以 drop-in 引入环境文件；此文件不在本轮授权修改范围。现有 nginx 的通用 proxy 可转发新 account 路径。
- kv-core 可选后续请求：当前 rsa_public_key 仅接受 2048-bit 模数。现在官方 [Google JWKS](https://www.googleapis.com/oauth2/v3/certs) 和 [Apple JWKS](https://appleid.apple.com/auth/keys) 为 RS256/2048-bit；未来较大模数会被拒绝，需要支持合理范围的 RSA 公钥大小。本轮未修改 kv-core。
- 显式跨 provider 绑定、账户删除、Apple code exchange/日常 refresh-token 生命周期仍需产品与 API 契约，未靠相同邮箱隐式连接账户。
- 真实 Google/Apple 系统流程、iOS 的 Google URL scheme 与 Apple provisioning、APNs/FCM 完整锁屏链路均等待相应注册和真机材料；没有将软件签发方测试写成这些验收通过。
