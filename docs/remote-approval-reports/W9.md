## Installer and release behavior

- Linux creates non-login `keyvalet-relay` and `keyvalet-relay-server` users, separate 0700 state directories and root-owned binaries/units. Configured public client configuration is root:relay 0640; an unpaired installation can leave it absent. The helper restarts only after the relay UID exists. An unpaired client is installed/enabled but not started; no account/device identifiers are fabricated.
- A server upgrade preserves an existing trusted configured unit and restores its previously active state after replacing the binary. The certificate directory is root-only. `keyvalet relay install` renders the nginx and server unit assets; operational setup requires an Origin CA certificate and nginx/systemd activation. The installer prints the three orange-cloud steps; no Tailscale/Caddy dependency is added.
- macOS provisions `dev.keyvalet.relay` only with the signed daemon path and a `PWCRJPY7YC` relay-client of the expected identifier. Authenticated public binding is required before bootstrap. Windows uses W3's SCM installer and the virtual `KeyValetRelay` service identity; queue/config DACLs grant different permissions. Native Windows identity/ACL acceptance is still untested.
- Runtime changes affect KeyValet's own entries: Claude user/current-project and Gemini `timeout=900000`, Codex/Grok `tool_timeout_sec=900`; Claude/Devin/Codex Stop, Cursor stop and Gemini AfterAgent invoke the W5 modes. JSON updates preflight duplicate/type/owner/symlink/size errors. TOML edits preserve unrelated fields and reject ambiguous forms rather than rewriting them. Inline TOML requires `tomlkit`; explicit tables work with Python 3.11's parser. Windows has its own conservative TOML boundary.
- Unix runtime receipts restore a prior timeout only if it still has the installer-owned value; later user edits are retained. The eight regression tests cover preservation, idempotency, removal of installer-created tables, malformed files and symlink refusal. PowerShell portable tests cover parse validity and TOML preservation/removal; Windows tests additionally enforce native DACL descriptors.
- `install.sh --uninstall` stops/removes the new services, owned nginx configuration, client configuration and runtime registrations before invoking the legacy cleanup. Queue ciphertext, certificates and service accounts are deliberately retained with the existing vault-preserving policy. Workflow packages provide an uninstall wrapper using this route. Direct legacy source uninstallers/bootstrap/standalone packagers remain T09 because they are outside the supplied ownership list.
- Release workflows include both relay binaries and service/deployment assets in macOS/Linux packages, sign every new macOS binary before existing notarization/Gatekeeper verification, and keep the protected release environment. Windows remains a manually signed artifact workflow. CI still executes all four workspace commands and includes installer checks; no security guard is weakened.

Manual privileged-shell audit: all three `sh -eu -c '…'` bodies contain zero apostrophes, including comments. External variables are assigned from positional arguments at the start of each body; loop/local variables are created inside it. Linux receives stage/UID/prior-active-state; removal receives platform/UID; macOS receives ten explicit arguments. `sh -n` is an additional check, not the source of this conclusion.
