agent 需要钥匙时，发生了什么

四步完成，秘密始终留在 agent 读不到的凭证库里。

  1. agent 发出请求

    通过 MCP 说明要用哪个凭证、为了什么。

  2. 你来批准

    Touch ID 弹窗显示凭证和这次授权放开的能力。逐次模式下显示真实请求——方法、域名、路径，以及已知 API 的关键业务字段——按一次，只授权这一笔。

  3. KeyValet 代为调用

    特权服务（macOS root 守护进程 / Linux 独立服务用户 / Windows 服务）注入 key，只发往你允许的域名，并抹掉响应里回显的秘密。

  4. agent 拿到结果

    返回响应，记录会话、目的和结果。会话结束，授权随之失效。

{%- else -%}

What happens when an agent needs a key

Four steps, and the secret never leaves a vault the agent can’t read.

  1. The agent asks

    Over MCP, naming the credential and saying why it needs it.

  2. You approve

    Touch ID shows the credential and what the grant allows. In per-use mode it shows the real request — method, host, path, plus the business fields that matter for known APIs — and one touch approves exactly that call.

  3. KeyValet makes the call

    A privileged service — the root daemon on macOS, a dedicated service user on Linux, a Windows service — injects the key, only toward hosts you allowed, and redacts anything that echoes it back.

  4. The agent gets the answer

    Response in; session, purpose and result logged. The grant ends with the session.

能保证什么，不能保证什么

凭证工具应该讲清楚自己的边界。完整的安全模型见 SECURITY.md，或本站的安全摘要。

能保证

  • 没有设备主人认证，任何凭证都用不了。
  • 协议凭证的长期秘密不出 root 进程；仅代理凭证永不返回明文。
  • 新增域名、放宽规则、覆盖或删除都要你确认，由 root 进程强制，而不是面向 agent 的服务端。
  • 每次使用都有记录，记录里从不出现秘密。

不能保证

  • 你授权过的 agent，可以在授权范围内滥用这次授权。
  • 目的是 agent 的自述，记录但不做核验；root 或 macOS 被攻破也防不住。
  • 用 credential_get 取出的值会进入 agent 的上下文。
{%- else -%}

What it guarantees, and what it doesn’t

A credential tool should be precise about its limits. The full model is in SECURITY.md, or read the security summary.

Guaranteed

  • No credential is used without device-owner authentication.
  • Long-term protocol secrets never leave the root helper; proxy-only credentials are never returned.
  • Adding hosts, loosening rules, overwriting or deleting needs your confirmation — enforced by root, not by the agent-facing server.
  • Every use is logged; secrets never are.

Not guaranteed

  • An agent you granted a credential can misuse that grant within its scope.
  • The purpose is the agent’s claim — recorded, never verified; compromised root or macOS is out of scope too.
  • Values you choose to reveal with credential_get are in the agent’s context.

安装

一条命令，macOS 和 Linux 通用：选对平台的发布包（macOS 签名并公证，Linux 提供校验值），要你输一次密码，配置好已安装的 Claude Code、Codex、Cursor、Grok、Devin CLI。重跑即升级。

curl -fsSL https://keyvalet.dev/install.sh | sh

macOS：Apple Silicon、macOS 14+。Linux：systemd、polkit、sudo，TPM 2.0（无 TPM 加 --software）。Windows 11 没有代码签名的正式包。发布包见下载页；签名状态见 Code signing policy。详情见使用指南。

然后直接对 agent 说：

“用 KeyValet 的 openai 模板保存我的 OpenAI key。”
“用 KeyValet 列出我的 OpenAI 模型。”

key 由你在原生对话框里输入，使用时由你用 Touch ID（Linux 上是 polkit）批准。agent 始终看不到它。

{%- else -%}

Install

One command for macOS and Linux: it picks your platform's release package (signed and notarized on macOS; checksums on Linux), asks for your password once, and sets up Claude Code, Codex, Cursor, Grok and Devin CLI if they’re installed. Run it again to upgrade.

curl -fsSL https://keyvalet.dev/install.sh | sh

macOS: Apple Silicon, macOS 14+. Linux: systemd, polkit, sudo, TPM 2.0 (or --software without one). Windows 11: unsigned release packages. See downloads and the Code signing policy for release status. Details in the guide.

Then just ask your agent:

“Store my OpenAI key in KeyValet with the openai template.”
“Use KeyValet to list my OpenAI models.”

You type the key into a native dialog, and approve its use with Touch ID (polkit on Linux). The agent never sees it.
